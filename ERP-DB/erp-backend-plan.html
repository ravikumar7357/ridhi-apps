R-one ERP Backend Plan

One plan, built from the team's review (“ideal vs now”, 28 Nov) and the work already done this week. Everything the ERP does goes through our own server; the browser only asks and shows. This is the plan we work on.

donenext / in progresswaitingneeds care

The goal in four lines

  1. Fast: a screen asks a question and gets a small answer (kilobytes, under 1 second), not whole registers (11–23 MB).
  2. Safe saves: one business action = one server call = all or nothing. No half-finished challans or approvals.
  3. Rules in one place: rights, locks, numbers and calculations live in server code with tests. The browser only hides buttons for comfort.
  4. Closed database: in the end only the server can touch the database. Nothing important can be done from a browser by hand.

How we work

  1. Every endpoint: read the old browser code → record a real input and answer → build → test against it → run both side by side → switch with a setting → remove the old path after two quiet weeks.
  2. Tests that must exist: same numbers as today, same rows as today, stop-halfway leaves nothing, repeat-a-call doubles nothing, each right allowed and refused.
  3. Database changes are numbered files in ERP-DB/changes/, each with its undo. Test project first. Nothing live in work hours without a yes.
  4. Secrets only in .env on the server, typed by Ravi; never in the code (the repository is public) or in chat.
  5. Anything that costs money is asked first, with ₹ per month.
