Sales Orders · सेल्स ऑर्डर

This is where a customer order is raised, sent for approval and approved into production. Nothing reaches the factory floor until an order is approved — approval writes one order-book line per SKU. The sales team also answers quantity and delete questions here.
यहाँ ग्राहक का ऑर्डर बनाया जाता है, approval के लिए भेजा जाता है और approve होकर production में जाता है। जब तक ऑर्डर approve नहीं होता, फैक्ट्री में उस पर कोई काम नहीं होता — approve होते ही हर SKU की एक लाइन order book में लिख जाती है। सेल्स टीम यहीं quantity और delete वाले सवालों का जवाब भी देती है।
1Find an order · ऑर्डर ढूँढें
Use the toolbar at the top of Sales Orders:
  • Status list: Draft, Awaiting approval, Returned to buyer, Approved.
  • Search box (order, buyer, channel or SKU) and the Ordered from/to dates. Clear empties them.
  • Each row shows Pieces, Cut and Made (as %), and In order book. Click Open to see every SKU of the order.
  • Refresh reads the latest data; Export downloads what is on screen.
Sales Orders के ऊपर वाले toolbar से:
  • Status लिस्ट: Draft, Awaiting approval, Returned to buyer, Approved।
  • Search box (ऑर्डर, buyer, channel या SKU) और Ordered की तारीख से/तक। Clear सब खाली कर देता है।
  • हर लाइन में Pieces, Cut और Made (% में) और In order book दिखता है। ऑर्डर के सारे SKU देखने के लिए Open दबाएँ।
  • Refresh नया डेटा लाता है; Export स्क्रीन वाला डेटा डाउनलोड करता है।
2Raise a new order · नया ऑर्डर बनाएँ
Click Sales Orders → + New sales order.
  • Fill Channel, Order date, Order type (Regular / New development). Requested delivery and Your own reference are optional.
  • The order number is made for you: CHANNEL-DDMMYYYY-NN (for example AMZ-01092026-01).
  • Add lines with + Add a line: SKU, Type, Priority (P1–P4), Qty, Delivery. The SKU must be in the master database.
  • Save keeps it as a Draft. Place order sends it for approval.
Sales Orders → + New sales order दबाएँ।
  • Channel, Order date, Order type (Regular / New development) भरें। Requested delivery और Your own reference ज़रूरी नहीं हैं।
  • ऑर्डर नंबर अपने आप बनता है: CHANNEL-DDMMYYYY-NN (जैसे AMZ-01092026-01)।
  • + Add a line से लाइनें जोड़ें: SKU, Type, Priority (P1–P4), Qty, Delivery। SKU master database में होना चाहिए।
  • Save से ऑर्डर Draft में रहता है। Place order से approval के लिए चला जाता है।
3Upload many lines from a file · फ़ाइल से बहुत सी लाइनें डालें
Inside the order form, click Template, fill it in Excel, then click Upload lines (.csv or .xlsx).
  • Columns: SKU, Qty, Priority, Order Type (Regular or New Development), Order Date, Delivery Date. Dates are DD-MM-YYYY.
  • Every row must have the same Order Date.
  • If even one row is wrong (unknown SKU, bad date, zero qty), nothing is loaded — fix the file and upload again.
  • If lines are already on the form, OK adds the new ones; Cancel replaces them all.
  • For the B2B channel the template has buyer columns (Brand Name, Item Name, Material, etc.). A SKU not in the master goes on the Custom SKUs list.
ऑर्डर फ़ॉर्म के अंदर Template दबाएँ, Excel में भरें, फिर Upload lines दबाएँ (.csv या .xlsx)।
  • कॉलम: SKU, Qty, Priority, Order Type (Regular या New Development), Order Date, Delivery Date। तारीख DD-MM-YYYY में।
  • हर लाइन में Order Date एक ही होनी चाहिए।
  • अगर एक भी लाइन गलत है (अनजान SKU, गलत तारीख, zero qty), तो कुछ भी नहीं चढ़ता — फ़ाइल ठीक करके फिर डालें।
  • फ़ॉर्म में पहले से लाइनें हों तो OK नई लाइनें जोड़ता है; Cancel सब बदल देता है।
  • B2B channel का template अलग है (Brand Name, Item Name, Material आदि)। जो SKU master में नहीं है वह Custom SKUs लिस्ट में चला जाता है।
4Approve or send back · Approve करें या वापस भेजें
An admin sees a Review button on orders that are Awaiting approval or Returned.
  • Choose Delivery: "One date for the whole order" (then fill That date) or "The date already on each line".
  • Approve into production writes the order-book lines. From then on cutting, issue and press can be booked against it.
  • Send back to the buyer needs a Remarks note saying what to change.
  • If an approved order shows "missing" SKUs, the Add the N missing button fills them in. Approving twice is safe.
जो ऑर्डर Awaiting approval या Returned हैं, उन पर admin को Review बटन दिखता है।
  • Delivery चुनें: "One date for the whole order" (फिर That date भरें) या "The date already on each line"।
  • Approve into production से order book में लाइनें लिख जाती हैं। इसके बाद ही cutting, issue और press की एंट्री हो सकती है।
  • Send back to the buyer के लिए Remarks में लिखना ज़रूरी है कि क्या बदलना है।
  • Approved ऑर्डर में कोई SKU "missing" दिखे तो Add the N missing बटन उसे भर देता है। दोबारा approve करने से कुछ डबल नहीं होता।
5Ask to change a quantity · Quantity बदलने की request
On an approved order: Open → Change qty on the SKU line.
  • Type the New quantity and Why it is changing (required), then Change it.
  • This only sends a request. The order and the order book do NOT change until someone in the Order Console approves it.
  • It cannot go below what is already cut, received or pressed. Only one request per SKU can wait at a time.
  • For many lines: Qty sheet downloads the approved lines on screen; fill "New qty" and "Why", then Qty import. An empty "New qty" means leave that line alone. You see what it will do before anything is written.
Approved ऑर्डर में: SKU लाइन पर Open → Change qty।
  • New quantity और Why it is changing (ज़रूरी) भरें, फिर Change it दबाएँ।
  • इससे सिर्फ़ request जाती है। जब तक Order Console में कोई approve न करे, ऑर्डर और order book नहीं बदलते।
  • जितना cut, receive या press हो चुका है, उससे कम नहीं कर सकते। एक SKU की एक समय में एक ही request रुक सकती है।
  • बहुत सी लाइनों के लिए: Qty sheet स्क्रीन के approved लाइनें डाउनलोड करता है; "New qty" और "Why" भरें, फिर Qty import करें। "New qty" खाली छोड़ा तो वह लाइन नहीं बदलेगी। लिखने से पहले दिखाया जाता है कि क्या होगा।
6Answer delete requests from production · Production की delete request का जवाब
When production asks to remove an order line, Sales Orders → Deletion requests (N) shows it. The sidebar also shows a count.
  • Tick the lines and press Delete ticked: the line is removed from the order book AND from the sales order, so re-approving cannot bring it back.
  • Or write a Note for production and press Keep ticked. The note is required to keep a line.
  • Work already booked (cut, issued, pressed) is not deleted — check the Work booked column first.
जब production कोई ऑर्डर लाइन हटाने को कहती है, तो वह Sales Orders → Deletion requests (N) में दिखती है। Sidebar में भी गिनती दिखती है।
  • लाइनों पर tick करें और Delete ticked दबाएँ: लाइन order book से भी और sales order से भी हट जाती है, दोबारा approve करने पर वापस नहीं आती।
  • या Note for production लिखकर Keep ticked दबाएँ। लाइन रखने के लिए note ज़रूरी है।
  • जो काम पहले हो चुका है (cut, issue, press) वह delete नहीं होता — पहले Work booked कॉलम देख लें।
Good to know. Anyone with this screen can raise an order and edit their OWN order while it is a Draft or Returned. Admins can review, edit and delete any order. Approving, sending back, changing quantities and the Qty sheet need "Can approve sales orders" (or admin). Deleting a sales order does not remove its order-book lines. A negative quantity on a line subtracts from what is already on order.
ध्यान दें। जिसके पास यह स्क्रीन है वह ऑर्डर बना सकता है और अपना ऑर्डर तभी बदल सकता है जब वह Draft या Returned हो। Admin कोई भी ऑर्डर review, edit और delete कर सकता है। Approve, वापस भेजना, quantity बदलना और Qty sheet के लिए "Can approve sales orders" का अधिकार (या admin) चाहिए। Sales order delete करने से उसकी order-book लाइनें नहीं हटतीं। लाइन में minus quantity डालने से पहले वाले ऑर्डर में से घटता है।

Order Console · ऑर्डर कंसोल

The order book: every approved order line and how far it has got — cut, issued, received, QC, pressed, in store and sent to FBA. Production and planning use it to see what is still to do, answer quantity changes, give work to printers and ask sales to delete lines.
यह order book है: हर approved ऑर्डर लाइन और उसका काम कहाँ तक पहुँचा — cut, issue, receive, QC, press, store में और FBA को भेजा। Production और planning टीम इससे देखती है कि क्या बाकी है, quantity बदलाव का जवाब देती है, printer को काम देती है और सेल्स से लाइन हटाने को कहती है।
1Read the order book · Order book पढ़ें
Keep the first list on Order book — every order.
  • Filter by order, article, subtype, color, size, status (Still open, Complete, Still to cut, Cutting done), source (Amazon / Shopify / B2B), brand, search and Ordered dates.
  • Columns: Ordered, Cut, Issued, Received, QC, Pressed, In store, To FBA, To cut, To make and Status.
  • Click a figure tile at the top (for example Still to make) to show only those lines; click again to show all.
  • Refresh re-reads everything; Export downloads the lines on screen.
पहली लिस्ट में Order book — every order रखें।
  • ऑर्डर, article, subtype, color, size, status (Still open, Complete, Still to cut, Cutting done), source (Amazon / Shopify / B2B), brand, search और Ordered तारीख से छाँटें।
  • कॉलम: Ordered, Cut, Issued, Received, QC, Pressed, In store, To FBA, To cut, To make और Status।
  • ऊपर किसी गिनती वाले tile (जैसे Still to make) पर click करें तो सिर्फ़ वही लाइनें दिखेंगी; फिर click करें तो सब दिखेंगी।
  • Refresh सब नया पढ़ता है; Export स्क्रीन की लाइनें डाउनलोड करता है।
2See one order start to finish · एक ऑर्डर शुरू से अंत तक
Click the Order No in any row. The window "Order … — start to finish" opens.
  • The top strip shows Ordered › With vendor › Back from vendor › Cut › Issued › Received › QC passed › Pressed › In store › To FBA.
  • Each SKU line shows which printer/vendor holds pieces, how many came back, and the promised date.
  • Waiting at tells you in one line where it is stuck (for example "Cutting — 40 to cut" or "Karigar — 20 out").
किसी भी लाइन में Order No पर click करें। "Order … — start to finish" वाली window खुलेगी।
  • ऊपर की पट्टी में Ordered › With vendor › Back from vendor › Cut › Issued › Received › QC passed › Pressed › In store › To FBA दिखता है।
  • हर SKU लाइन में दिखता है कि किस printer/vendor के पास कितने पीस हैं, कितने वापस आए और कौन सी तारीख का वादा है।
  • Waiting at एक लाइन में बताता है कि काम कहाँ रुका है (जैसे "Cutting — 40 to cut" या "Karigar — 20 out")।
3Approve quantity changes · Quantity बदलाव approve करें
When sales asks to change a quantity, a button "N quantity changes to approve" appears at the top, the sidebar shows a count, and the line shows a yellow "qty asked" pill with an Answer link.
  • Click the button or Answer. The window shows Now, Asked, Made so far, Why and who asked.
  • Tick and press Approve ticked — only now do the sales order and the order book change.
  • To refuse, write a reason and press Turn down ticked.
  • A red row "cannot go below this" will be refused, because those pieces are already made.
जब सेल्स quantity बदलने को कहती है, तो ऊपर "N quantity changes to approve" बटन आता है, sidebar में गिनती दिखती है, और लाइन पर पीला "qty asked" निशान और Answer link दिखता है।
  • बटन या Answer पर click करें। Window में Now, Asked, Made so far, Why और किसने माँगा, दिखता है।
  • Tick करके Approve ticked दबाएँ — तभी sales order और order book बदलते हैं।
  • मना करने के लिए कारण लिखें और Turn down ticked दबाएँ।
  • लाल लाइन "cannot go below this" approve नहीं होगी, क्योंकि उतने पीस बन चुके हैं।
4Give lines to a printer · Printer को लाइनें दें
Tick lines on the left, then press Assign printer to N and choose the printer. Or use Assign / Printer on one row.
  • The Printing column shows how many came back of how many were given, and which vendor has them.
  • A line can only be cut after its printer records it with Printed.
  • Vendor pieces for one SKU are shared between orders once: open orders first, oldest first.
बाईं ओर लाइनों पर tick करें, फिर Assign printer to N दबाकर printer चुनें। या एक लाइन पर Assign / Printer दबाएँ।
  • Printing कॉलम दिखाता है कि जितने दिए उनमें से कितने वापस आए, और किस vendor के पास हैं।
  • Printer जब Printed से एंट्री कर दे, तभी उस लाइन की cutting हो सकती है।
  • एक SKU के vendor वाले पीस ऑर्डरों में एक ही बार बाँटे जाते हैं: पहले खुले ऑर्डर, सबसे पुराने पहले।
5Ask sales to delete a line · सेल्स से लाइन हटाने को कहें
Tick the line(s), press Ask sales to delete N, write Why should these go? and press Send to the sales team.
  • The line stays in the order book with a "delete asked" pill until Sales Orders answers.
  • If sales keeps it, you see "sales kept it:" with their note.
लाइन पर tick करें, Ask sales to delete N दबाएँ, Why should these go? में कारण लिखें और Send to the sales team दबाएँ।
  • जब तक Sales Orders जवाब न दे, लाइन order book में "delete asked" निशान के साथ रहती है।
  • अगर सेल्स उसे रखती है तो "sales kept it:" के साथ उनका note दिखेगा।
6Shopify views · Shopify वाले व्यू
Change the first list to Shopify — by SKU, combined or Shopify — by order.
  • Entry on a line records cut, issue, receive and press for it; Handover gives a finished line to the shipping team (it can be undone).
  • On the by-SKU view: Bulk entry, Entry sheet and Upload entry sheet record a whole SKU at once, oldest order first.
  • Printer sheet / Upload printer sheet give Shopify lines to printers.
पहली लिस्ट को Shopify — by SKU, combined या Shopify — by order पर करें।
  • लाइन पर Entry से उसका cut, issue, receive और press दर्ज होता है; Handover से तैयार लाइन shipping टीम को दी जाती है (ज़रूरत हो तो वापस ली जा सकती है)।
  • By-SKU व्यू में: Bulk entry, Entry sheet और Upload entry sheet से पूरा SKU एक साथ दर्ज होता है, पहले सबसे पुराना ऑर्डर।
  • Printer sheet / Upload printer sheet से Shopify लाइनें printers को दी जाती हैं।
Good to know. Anyone with the Order Console (or an admin) can approve or turn down quantity changes and ask sales to delete lines. Assigning printers on the order book needs "Can assign printers on the order book"; Shopify printer sheets need the Shopify assign right; bulk entries need "Can edit production entries". The table shows the first 600 lines — use filters or Export. A red message about rows with no Order ID means pieces were made but cannot be counted against any order.
ध्यान दें। जिसके पास Order Console है (या admin), वह quantity बदलाव approve/मना कर सकता है और सेल्स से लाइन हटाने को कह सकता है। Order book में printer देने के लिए "Can assign printers on the order book" अधिकार चाहिए; Shopify printer sheet के लिए Shopify assign अधिकार; bulk entry के लिए "Can edit production entries"। टेबल में पहली 600 लाइनें दिखती हैं — filter या Export इस्तेमाल करें। अगर लाल संदेश में बिना Order ID वाली एंट्री लिखी हो, तो वे पीस बने हैं पर किसी ऑर्डर में गिने नहीं जा रहे।

Cutting Data · कटिंग डेटा

The cutting register. The cutting team records how many pieces of a SKU were cut, against which order, from which fabric, and how much cloth was used and wasted. Every later step (issue to karigar, press) is limited by these figures.
यह कटिंग रजिस्टर है। कटिंग टीम यहाँ लिखती है कि किस SKU के कितने पीस, किस ऑर्डर के लिए, किस कपड़े से कटे, और कितना कपड़ा लगा व कितना waste हुआ। आगे का सारा काम (कारीगर को issue, press) इन्हीं गिनतियों से सीमित होता है।
1Open the entry form and pick the item · एंट्री फ़ॉर्म खोलें और आइटम चुनें
Click Cutting Data → + New cutting entry.
  • Choose Article type, Subtype, Colour, Size — the SKU fills in by itself.
  • Or type the SKU in the SKU box; the four boxes fill back.
  • Only SKUs that are on some order can be picked.
Cutting Data → + New cutting entry दबाएँ।
  • Article type, Subtype, Colour, Size चुनें — SKU अपने आप भर जाएगा।
  • या SKU box में SKU लिखें; चारों box अपने आप भर जाएँगे।
  • सिर्फ़ वही SKU चुने जा सकते हैं जो किसी ऑर्डर में हैं।
2Choose the order and fill the cut · ऑर्डर चुनें और कटिंग भरें
  • Select an Order ID… — each order shows "N of M left". The line below says how many may still be cut.
  • Pieces, Fabric (from the Fabric Type master), and the cutting date.
  • Fabric used (m) is worked out for you — type over it with what the table really took. Waste (m) is optional.
  • Remarks if needed, then Save entry.
  • Select an Order ID… — हर ऑर्डर के साथ "N of M left" दिखता है। नीचे की लाइन बताती है कि अभी कितने और कट सकते हैं।
  • Pieces, Fabric (Fabric Type master से) और कटिंग की तारीख भरें।
  • Fabric used (m) अपने आप भरता है — असल में जितना कपड़ा लगा वह लिख दें। Waste (m) ज़रूरी नहीं है।
  • ज़रूरत हो तो Remarks, फिर Save entry दबाएँ।
3Check the register · रजिस्टर देखें
Filter by order, article, subtype, color, size, Anyone's entry (who entered it), search, and the Cut dates.
  • The tiles show pieces cut, fabric used, waste and waste %. Waste above 10% shows in red.
  • A dash (—) means nobody measured the cloth for that entry.
  • Export downloads the rows on screen; Refresh re-reads.
ऑर्डर, article, subtype, color, size, Anyone's entry (किसने एंट्री की), search और Cut की तारीखों से छाँटें।
  • Tiles में कटे पीस, लगा कपड़ा, waste और waste % दिखता है। 10% से ज़्यादा waste लाल दिखता है।
  • डैश (—) का मतलब है उस एंट्री का कपड़ा नापा नहीं गया।
  • Export स्क्रीन की लाइनें डाउनलोड करता है; Refresh नया पढ़ता है।
4Correct a mistake · गलती ठीक करें
Click Edit on the row. You can change Pieces, Fabric and Remarks, then Save.
  • The SKU cannot be changed — a different SKU is a new entry.
  • The cut date and Delete are for admins only.
लाइन पर Edit दबाएँ। Pieces, Fabric और Remarks बदल सकते हैं, फिर Save दबाएँ।
  • SKU नहीं बदल सकते — दूसरा SKU मतलब नई एंट्री।
  • कटिंग की तारीख बदलना और Delete सिर्फ़ admin कर सकते हैं।
Good to know. The app refuses an entry when: the SKU is not in the master database; no Order ID is chosen; the pieces are more than ordered minus already cut (rejected pieces are given back); the fabric is not in the Fabric Type master; or the month is frozen. The Edit button needs "Can edit production entries" (or admin).
ध्यान दें। ऐप एंट्री नहीं लेगा अगर: SKU master database में नहीं है; Order ID नहीं चुना; पीस "ऑर्डर माइनस पहले से कटे" से ज़्यादा हैं (reject हुए पीस वापस गिने जाते हैं); कपड़ा Fabric Type master में नहीं है; या वह महीना freeze है। Edit बटन के लिए "Can edit production entries" अधिकार (या admin) चाहिए।

Job Work Register · जॉब वर्क रजिस्टर

The register of pieces given to karigars (tailors) and received back. Each row is one issue: who got it, which SKU, which order, how many issued, received, rejected and pending. It drives the order balance and karigar pay, so enter it carefully.
यह कारीगरों (दर्ज़ी) को दिए गए और वापस आए पीस का रजिस्टर है। हर लाइन एक issue है: किसे दिया, कौन सा SKU, कौन सा ऑर्डर, कितने issue, receive, reject और pending। इसी से ऑर्डर का बैलेंस और कारीगर की पेमेंट बनती है, इसलिए ध्यान से एंट्री करें।
1Issue pieces to a karigar · कारीगर को पीस issue करें
Click Job Work Register → + New entry.
  • Select Order ID first — it lists orders with "pcs open". Then the item boxes show only what that order needs.
  • Pick Employment type and type/pick the Employee name (must be on that list).
  • Choose Article type, Subtype, Colour, Size (or type the SKU), enter Issue pieces, date and remarks, then press Issue.
  • The line under the form shows how many may be issued, and says if cutting is holding it back.
  • Clear empties the form without saving.
Job Work Register → + New entry दबाएँ।
  • पहले Select Order ID चुनें — इसमें "pcs open" वाले ऑर्डर दिखते हैं। फिर आइटम वाले box में सिर्फ़ उस ऑर्डर की चीज़ें आती हैं।
  • Employment type चुनें और Employee name लिखें/चुनें (नाम उस लिस्ट में होना चाहिए)।
  • Article type, Subtype, Colour, Size चुनें (या SKU लिखें), Issue pieces, तारीख और remarks भरें, फिर Issue दबाएँ।
  • फ़ॉर्म के नीचे वाली लाइन बताती है कि कितने issue हो सकते हैं, और क्या cutting की वजह से रुका है।
  • Clear बिना save किए फ़ॉर्म खाली करता है।
2One-off item and materials · एक बार का आइटम और सामान
  • Tick Custom Order for a one-off item with no SKU: colour and size become free text, no Order ID is needed, and a SKU is made (or an existing matching one is reused).
  • For zip or ruffle items, "Also issued with these pieces" shows the zippers and ruffle cloth worked out. Type over them if a different amount went. They are taken off stock when you save.
  • बिना SKU वाले एक बार के आइटम के लिए Custom Order पर tick करें: colour और size हाथ से लिखें, Order ID नहीं चाहिए, और नया SKU बनता है (या पहले से मिलता-जुलता SKU इस्तेमाल होता है)।
  • Zip या ruffle वाले आइटम में "Also issued with these pieces" में zipper और ruffle कपड़ा अपने आप भरता है। जितना असल में दिया, वह लिख दें। Save करते ही ये स्टॉक से घट जाते हैं।
3Receive pieces back · पीस वापस लें
In the register, find the row and use the Receive column.
  • Type the pieces that came back in +recv — it is ADDED to what was already received.
  • Type the TOTAL rejected in rej.
  • It saves when you leave the box. When nothing is pending the row becomes Done.
  • Received plus rejected can never be more than issued.
रजिस्टर में लाइन ढूँढें और Receive कॉलम इस्तेमाल करें।
  • +recv में जितने पीस वापस आए वह लिखें — यह पहले वाले received में जुड़ जाता है।
  • rej में कुल reject पीस लिखें।
  • Box से बाहर आते ही save हो जाता है। जब कुछ pending न रहे तो लाइन Done हो जाती है।
  • Received और rejected मिलाकर issue से ज़्यादा नहीं हो सकते।
4Tell the karigar on WhatsApp · कारीगर को WhatsApp करें
In the WhatsApp column press Issue or Recv. WhatsApp opens with the message ready — press Send there.
  • A grey button shows why it cannot be used (no number, nothing received, before the cutoff date).
  • Once sent, only an admin can send it again.
WhatsApp कॉलम में Issue या Recv दबाएँ। WhatsApp संदेश के साथ खुलेगा — वहाँ Send दबाएँ।
  • धुंधला बटन बताता है कि क्यों नहीं चलेगा (नंबर नहीं, कुछ receive नहीं हुआ, cutoff तारीख से पहले का)।
  • एक बार भेजने के बाद दोबारा सिर्फ़ admin भेज सकता है।
5Correct or remove an entry · एंट्री ठीक करें या हटाएँ
Click Edit on an open row, change the employee, pieces or remarks, and press Save changes.
  • Only an admin can change the SKU and the dates, and Delete.
  • Others press Ask to delete and give a reason. Admins answer from the Deletion requests button (Delete it / Keep it).
खुली लाइन पर Edit दबाएँ, कर्मचारी, पीस या remarks बदलें और Save changes दबाएँ।
  • SKU और तारीख बदलना, और Delete सिर्फ़ admin कर सकता है।
  • बाकी लोग Ask to delete दबाकर कारण लिखें। Admin Deletion requests बटन से जवाब देता है (Delete it / Keep it)।
6Find entries · एंट्री ढूँढें
Filter by type, employee, Anyone's entry, article, subtype, color, size, status (Open, Completed, Has pending), search and Issued dates. Click a tile (Issued, Received, Rejected, Pending pieces, Completed, Open) to show only those rows. Export gives all matching rows.
Type, कर्मचारी, Anyone's entry, article, subtype, color, size, status (Open, Completed, Has pending), search और Issued की तारीख से छाँटें। किसी tile (Issued, Received, Rejected, Pending pieces, Completed, Open) पर click करें तो सिर्फ़ वही लाइनें दिखेंगी। Export सारी मिलती लाइनें देता है।
Good to know. The app refuses an issue when: the employee is not on the list; the SKU is not in the master (use Custom Order); no Order ID is chosen; issued would go over the order; or more is issued than has been cut (for items that need cutting). A zip item is refused if the zippers are not in stock. The same issue saved twice within two minutes asks you first — it would be a second payment. Edit needs "Can edit production entries" (or admin); completed rows cannot be edited from the register.
ध्यान दें। ऐप issue नहीं लेगा अगर: कर्मचारी लिस्ट में नहीं है; SKU master में नहीं है (Custom Order लें); Order ID नहीं चुना; issue ऑर्डर से ज़्यादा हो जाए; या जितना कटा है उससे ज़्यादा issue हो (जिन आइटम की cutting ज़रूरी है)। Zip वाला आइटम तब नहीं जाएगा जब zipper स्टॉक में न हों। वही issue दो मिनट के अंदर दोबारा save करें तो पहले पूछा जाएगा — यह दूसरी पेमेंट बन जाएगी। Edit के लिए "Can edit production entries" (या admin) चाहिए; Done लाइन रजिस्टर से edit नहीं होती।

Press Inventory · प्रेस इन्वेंटरी

The press register. The press team records finished pieces that come off the press, against an order. These counts show as Pressed in the Order Console and close the order line.
यह प्रेस रजिस्टर है। प्रेस टीम यहाँ press होकर तैयार हुए पीस, ऑर्डर के हिसाब से, दर्ज करती है। यही गिनती Order Console में Pressed में दिखती है और ऑर्डर लाइन पूरी करती है।
1Make a press entry · प्रेस एंट्री करें
Click Press Inventory → + New press entry.
  • Select Order ID — it lists orders with "pcs open", oldest first.
  • Choose Article type, Subtype, Colour, Size (or type the SKU).
  • The line below shows how many may still be pressed on that order.
  • Enter Pieces, the date and remarks, then press Save entry.
Press Inventory → + New press entry दबाएँ।
  • Select Order ID चुनें — इसमें "pcs open" वाले ऑर्डर, सबसे पुराने पहले, दिखते हैं।
  • Article type, Subtype, Colour, Size चुनें (या SKU लिखें)।
  • नीचे की लाइन बताती है कि उस ऑर्डर पर अभी कितने और press हो सकते हैं।
  • Pieces, तारीख और remarks भरें, फिर Save entry दबाएँ।
2Check the register · रजिस्टर देखें
Filter by order, article, subtype, color, size, search, and the Entered dates. The table shows the first 600 rows; Export covers all of them. Refresh re-reads the latest data.
ऑर्डर, article, subtype, color, size, search और Entered तारीख से छाँटें। टेबल में पहली 600 लाइनें दिखती हैं; Export में सब आती हैं। Refresh नया डेटा पढ़ता है।
3Correct a mistake · गलती ठीक करें
Click Edit on the row, change Pieces or Remarks, and press Save. The SKU cannot be changed. The entry date and Delete are for admins only.
लाइन पर Edit दबाएँ, Pieces या Remarks बदलें और Save दबाएँ। SKU नहीं बदल सकते। तारीख बदलना और Delete सिर्फ़ admin कर सकता है।
Good to know. The app refuses a press entry when: the SKU is not in the master database; no Order ID is chosen; the order has no line for that SKU; pressed would go over what was ordered; or the month is frozen. The Edit button needs "Can edit production entries" (or admin).
ध्यान दें। ऐप press एंट्री नहीं लेगा अगर: SKU master database में नहीं है; Order ID नहीं चुना; ऑर्डर में उस SKU की लाइन नहीं है; press ऑर्डर से ज़्यादा हो जाए; या वह महीना freeze है। Edit बटन के लिए "Can edit production entries" (या admin) चाहिए।
